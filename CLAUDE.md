# Prosjektkontekst før KI-arbeid

Les først [gjeldende prosjektstatus](docs/PROSJEKTSTATUS.md), [dokumentasjonsrevisjonen](docs/DOKUMENTASJONSREVISJON-2026-11-25.md), [README](README.md) og [innleveringssjekklisten](docs/DOKUMENTASJON-SJEKKLISTE.md). Bruk faktiske GitHub- og Render-resultater ved nye endringer. Spør ikke brukeren på nytt om repo, tjenester, gren eller allerede avklarte forhold når disse kan leses her. Skillet mellom historisk rapport og gjeldende status må respekteres.

**Formål nå:** Fullføre IBE160-studentprosjektet og innleveringsdokumentasjonen, ikke starte nye test-/funksjonsrunder uten konkret behov. Skolens maltilpassede solo-refleksjonsrapport er `docs/REFLEKSJONSRAPPORT-MAL-TILPASSET-SOLO.md`. Behold ekte prosjekt- og feilhistorikk; dokumenter senere rettelser som nye daterte notater. Piloten er kun for eksperimentelle funksjoner, ikke standard for ordinære feilrettinger.

## Sesjonslogg

Når en oppgave eller økt avsluttes, før sluttoppsummeringen, bruk `sesjonslogg`-skillen: dokumenter Oppgave + Plan + Resultat + åpne punkter i `.logs/<bruker>/`, og før åpne punkter i `.logs/<bruker>/issues.md`. Skillen committer loggfila lokalt; push gjør du selv. Gruppens egne regler for commit og språk gjelder foran dette.
